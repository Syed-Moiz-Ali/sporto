2. CLEAN ARCHITECTURE LAYER SPECIFICATIONS
--------------------------------------------------------------------------------

A. DOMAIN LAYER (Pure Dart - Business Logic & Contracts):
   - Entities:
     * PlayerEntity (id, name, role, jerseyNumber)
     * TeamEntity (id, name, logoEmoji, players)
     * BallScoreEntity (ballNumber, runs, isWide, isNoBall, isWicket, wicketType, strikerName, bowlerName)
     * TossResultEntity (winnerTeamId, choice: BAT/BOWL)
     * CricketMatchEntity (id, tournamentName, teamA, teamB, venue, scheduledTime, totalOvers, matchDurationMinutes, breakDurationMinutes, status, tossResult, teamAScore, teamAWickets, teamAOvers, teamBScore, teamBWickets, teamBOvers, currentInning, currentOverBalls, commentary, refereeName, isVerifiedByReferee, syncStatus)
     * TournamentEntity (id, name, category, startDate, oversPerInning, totalTeams, matchDurationMinutes, breakMinutes, venues, entryFee, prizePool, status, syncStatus)
     * Enums: SyncStatus (synced, pendingSync, syncFailed), MatchStatus (upcoming, verification, toss, live, completed), TossChoice (bat, bowl), WicketType (bowled, caught, runOut, lbw, stumped, hitWicket, retiredHurt)

   - Repository Interfaces:
     * ITournamentRepository: getTournaments(), createTournament(), syncPendingTournaments()
     * IMatchRepository: getMatches(), getMatchById(), verifyMatch(), conductToss(), recordBallScore(), syncPendingMatches()
     * ISyncRepository: checkConnectivity(), watchConnectivity(), syncAllPendingData()

   - Use Cases:
     * GetTournamentsUseCase
     * CreateTournamentUseCase
     * GetMatchesUseCase
     * VerifyMatchUseCase
     * ConductTossUseCase
     * RecordBallScoreUseCase
     * SyncPendingDataUseCase

B. DATA LAYER (Local-First Persistence & Network):
   - HiveLocalDataSource: Persistent Hive boxes:
     * 'sporto_tournaments_box'
     * 'sporto_matches_box'
     * 'sporto_pending_sync_box'
   - Repository Implementations:
     * TournamentRepositoryImpl: Saves new tournaments to Hive with SyncStatus.pendingSync when offline, or SyncStatus.synced when online.
     * MatchRepositoryImpl: Handles scorekeeping updates locally in Hive first, updates team scores, wickets, overs, commentary, and triggers background sync.
     * SyncRepositoryImpl: Monitors network status via connectivity_plus, auto-triggers sync when back online.

C. PRESENTATION LAYER (BLoCs & Design System):
   - BLoCs:
     * TournamentBloc: LoadTournamentsEvent, AddTournamentEvent -> TournamentState
     * MatchBloc: LoadMatchesEvent, VerifyMatchEvent, ConductTossEvent, RecordBallEvent -> MatchState
     * SyncBloc: CheckConnectionEvent, ConnectivityStatusChangedEvent, TriggerSyncEvent -> SyncState
   - Theme (SportoTheme):
     * Primary Green: #00C853
     * Accent Green: #05C662
     * Dark Background: #121418
     * Surface Dark: #1B1E24
     * Card Background: #252932
     * Card Border: #2E3440
     * Accent Yellow: #FFD600
     * Live Red: #FF3D00
     * Typography: Space Grotesk (Titles & Headers), Inter (Body text)
   - Shared Widgets:
     * SyncIndicatorBadge: Visual badge showing "Online & Synced" (Green) or "Offline Mode (Saved Locally)" (Orange).

3. APPLICATION 1: SPORTO PARTNER APP REQUIREMENTS
--------------------------------------------------------------------------------
Target Users: Tournament Organizers, Ground Owners, League Hosts.

Features & Screen Workflows:
1. AppBar & Header:
   - "SPORTO Partner" title with trophy icon.
   - SyncIndicatorBadge showing real-time connectivity & local-first sync state.
2. Bottom Navigation Tabs:
   - Tab 1: Tournaments (List of tournaments, quick stats summary: Active, Open Reg.).
   - Tab 2: Live Matches (Real-time monitoring of ongoing matches across grounds).
   - Tab 3: Grounds (Ground & turf slot listings, hourly pricing).
   - Tab 4: Earnings (Financial revenue summary, tournament collection analytics).
3. Multi-Step Tournament Creation Wizard:
   - Step 1 (Basic Info): Tournament Name, Category (T10 Knockout, T20, Box Cricket).
   - Step 2 (Format): Overs per Inning, Total Teams.
   - Step 3 (Timers & Schedule): Match Duration (minutes), Innings Break Duration (minutes).
   - Step 4 (Fees & Venues): Entry Fee ($), Prize Pool ($), Venue selection.
   - Action: Save Tournament dispatches AddTournamentEvent -> Saves instantly to Hive (local-first) -> Syncs to Cloud API.

4. APPLICATION 2: SPORTO REFEREE APP REQUIREMENTS
--------------------------------------------------------------------------------
Target Users: Official Umpires, Match Referees, Scorekeepers.

Features & Screen Workflows:
1. Referee Home Dashboard:
   - Official Umpire Portal Banner with Referee Name & Badge ID (#UM-9921).
   - SyncIndicatorBadge in AppBar.
   - Assigned Matches List with live status badges (Upcoming, Verification, Toss, Live, Completed).
   - Action Button dynamically updates based on match state: "Verify Roster" -> "Conduct Toss" -> "Open Scorekeeper" -> "View Result".
2. Pre-Match Verification Checklist:
   - Checklist items: Team A Roster Verified, Team B Roster Verified, Ground Boundary Checked, Match Leather Balls Handed to Captains.
   - Action: "Verify & Proceed to Coin Toss" dispatches VerifyMatchEvent.
3. Conduct Coin Toss Screen:
   - Interactive Animated Coin Flip Widget (Heads/Tails).
   - Toss Winner selector (Team A vs Team B).
   - Toss Decision selector (Elect to BAT vs Elect to BOWL).
   - Action: "Start Live Scorekeeper Engine" dispatches ConductTossEvent.
4. Live Ball-by-Ball Scorekeeper Engine:
   - Live Scorecard Header: Batting Team Emoji & Name, Score/Wickets, Overs, Target.
   - Quick Run Buttons: [0], [1], [2], [3], [4], [6].
   - Extras Buttons: WIDE (+1), NO BALL (+1).
   - Wicket Modal: BOWLED, CAUGHT, RUN OUT, LBW, STUMPED, HIT WICKET, RETIRED HURT.
   - Player Roles: Striker & Bowler indicator with auto-over swap.
   - Live Ball Commentary Feed (chronological log of every ball).
   - Action: Every score entry dispatches RecordBallEvent -> Saves to Hive locally first -> Syncs to Cloud.
5. Official Match Result Screen:
   - Winner announcement banner with confetti/trophy icon.
   - Final scorecard comparison (Team A Score vs Team B Score).
   - Super Over / Tie settlement notification.
   - Action: "Submit Match Result & Return to Home".

5. OFFLINE-FIRST & HYBRID CLOUD SYNC RULES FOR LLM AGENTS
--------------------------------------------------------------------------------
1. ALL user actions MUST mutate local Hive storage first before attempting network HTTP calls.
2. If internet connection is lost or offline, the UI MUST NOT block or fail; it marks syncStatus = SyncStatus.pendingSync and displays the SyncIndicatorBadge in Orange mode.
3. When internet connectivity is restored, SyncBloc automatically triggers SyncPendingDataUseCase to push all pending Hive records to the cloud REST API and updates status to SyncStatus.synced.
4. Clean Architecture MUST be preserved across all packages. Domain entities must remain pure with zero framework lock-in.
