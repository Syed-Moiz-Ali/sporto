STRICT ARCHITECTURAL REQUIREMENTS:
  1. Full Event-Driven BLoC Pattern (Strictly `Bloc<Event, State>` - NO Cubits!):
     - Every user interaction or system trigger is an explicit Event class dispatched via `bloc.add(Event())`.
     - State transitions are strictly controlled via `on<Event>((event, emit) async => ...)` handlers.
  2. Clean Architecture (Domain, Data, Presentation):
     - Domain: Pure Dart. Entities, Repository Interfaces, Use Cases. Zero framework/UI lock-in.
     - Data: Hive Local Data Sources, Remote REST API Client, Repository Implementations.
     - Presentation: BLoCs, Glassmorphism Design System, Screens.
  3. Multi-Sport Engine Strategy Architecture (Cricket engine first, extensible to Football, Basketball, etc.).
  4. Local-First Hive Storage & Background Sync Queue.
  5. Melos Monorepo Structure: 5 Decoupled Packages + 2 Mobile Applications.

2. FULL EVENT-DRIVEN BLOC SPECIFICATIONS (NO CUBITS)
================================================================================

All state management across apps and core strictly uses full BLoC classes:

A. `ConnectivityBloc` (packages/core):
   - Events:
     * `StartConnectivityWatcherEvent`
     * `ConnectivityStatusChangedEvent(bool isConnected)`
     * `TriggerSyncQueueEvent`
   - States:
     * `ConnectivityInitialState`
     * `ConnectivityStatusState(bool isConnected, SyncStatus syncStatus, int pendingItemsCount)`
   - Handler:
     `on<ConnectivityStatusChangedEvent>((event, emit) async => ...)`

B. `TournamentBloc` (apps/partner_app):
   - Events:
     * `LoadTournamentsEvent`
     * `FilterTournamentsBySportEvent(SportType sportType)`
     * `AddTournamentEvent(TournamentEntity tournament)`
   - States:
     * `TournamentInitialState`
     * `TournamentLoadingState`
     * `TournamentLoadedState(List<TournamentEntity> tournaments, SportType selectedSport)`
     * `TournamentOperationSuccessState(String message)`
     * `TournamentErrorState(String errorMessage)`
   - Handlers:
     `on<LoadTournamentsEvent>(_onLoadTournaments);`
     `on<AddTournamentEvent>(_onAddTournament);`

C. `MatchScoringBloc` (apps/referee_app):
   - Events:
     * `LoadMatchDetailEvent(String matchId)`
     * `VerifyMatchRosterEvent(String matchId, bool rosterA, bool rosterB, bool boundary, bool balls)`
     * `ConductTossEvent(String matchId, String winnerTeamId, TossChoice choice)`
     * `RecordBallEvent(String matchId, BallScoreEntity ballScore)`
     * `CompleteMatchEvent(String matchId)`
   - States:
     * `MatchScoringInitialState`
     * `MatchScoringLoadingState`
     * `MatchScoringLoadedState(CricketMatchEntity match)`
     * `MatchCompletedState(CricketMatchEntity match, String winnerName)`
     * `MatchScoringErrorState(String errorMessage)`
   - Handlers:
     `on<RecordBallEvent>(_onRecordBall);`
     `on<ConductTossEvent>(_onConductToss);`

5. IMPLEMENTATION ROADMAP
================================================================================

PHASE 1: Monorepo Foundation & Package Initialization
  - Setup Melos monorepo configuration, `melos.yaml`, root `pubspec.yaml`, and 5 package skeleton files.

PHASE 2: Core Infrastructure & Glassmorphism UI Kit
  - Build `packages/core`: `ConnectivityBloc` (Full BLoC pattern), Hive initialization, `SyncQueue` box.

  - Build `packages/shared_domain`: Define Freezed + Hive entities (`CricketMatchEntity`, `TournamentEntity`), Repository Interfaces, Use Cases, `ISportScoreEngine`, `SportEngineFactory`.
  - Build `packages/partner_data` & `packages/referee_data`: Hive data sources and repository implementations. Run `build_runner`.

PHASE 4: Partner App (`apps/partner_app`) Development
  - Build `TournamentBloc` (`Bloc<TournamentEvent, TournamentState>`).
  - Build 4-tab Glass Navigation, Multi-Sport Tournament Creation Wizard, Live Grounds Monitor, Earnings.

PHASE 5: Referee App (`apps/referee_app`) Development
  - Build `MatchScoringBloc` (`Bloc<MatchScoringEvent, MatchScoringState>`).
  - Build Referee Portal (#UM-9921), Pre-Match Roster Verification, 3D Coin Toss Simulator, Live Scorekeeper Engine, Result view.

PHASE 6: Offline Sync Integration & End-to-End Verification
  - Connect `ConnectivityBloc` to auto-trigger background sync upon internet restoration.
  - Run build checks across all packages and test user workflows.
